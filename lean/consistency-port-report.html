01 / Orientation

What this port is - and is not

It is a hand-written, unbounded Lean translation of the Veil client consistency model. It is not yet a translation of CCF Raft, a complete proof of all translated properties, or a runtime trace validator.

The key boundary reachableProved establishes a 19-clause ProvedBundle. Seventeen translated clauses, including the final real-time safety property, remain open. No assumption hides them.
Model scope

Client-visible consistency

Transactions, ledger branches, sequence positions, requests, responses, and commit/invalid status observations.

Proof scope

Unbounded safety

The theorem quantifies over abstract domains and every state built by the inductive Reachable relation.

Out of scope

Consensus mechanics

No servers, votes, messages, quorums, terms, leaders, fairness, liveness, or CCF Raft implementation trace replay.

02 / Mental model

Translate relations, not model-checker behavior

TLA+ and Lean can state the same transition system, but they answer different questions by default. TLC searches finite instances; this Lean development constructs a proof for all inhabitants of its abstract types.

TLA+ / TLC lens

  • Init /\ [][Next]_vars defines behaviors.
  • TLC enumerates reachable concrete states.
  • An invariant violation produces a counterexample trace.
  • Bounds, symmetry, and constraints control tractability.
~

Lean lens

  • initialState is a value.
  • Step s s' is an inductive proposition.
  • Reachable is the reflexive transition closure.
  • Induction proves a proposition for every reachable state.

07 / Trace validation

Trace validation currently lives in TLA+/TLC

The pure Lean project does not parse NDJSON or replay CCF Raft events. Examples.lean proves a constructed request/execute/response path is reachable; that is a non-vacuity test, not implementation trace validation.

Current TLC path

Search for a matching refinement

  1. Raft driver emits raft_trace NDJSON lines.
  2. Traceccfraft.tla maps each log function to zero or more model actions.
  3. Missing state is chosen nondeterministically.
  4. TLC keeps possible paths and requires at least one full match.
  5. CCF invariants are constraints during replay.
Important complication

One log event is not always one model step

The implementation piggybacks operations. Trace validation composes steps such as UpdateTerm then message handling, and sometimes two receive actions. Any Lean validator must represent those hidden intermediate states.

A Lean-native design that scales

NDJSONObserved, partial implementation event.
Untrusted searchChooses parameters, hidden states, and step counts.
CertificateZero-or-more model steps per observation, including intermediates.
Lean checkerChecks the reflexive-transitive Step witnesses and observations.
Soundness theoremAccepted trace has a reachable matching execution.
TLC's current existence check is one-sided TraceMatched is a "poor man's hyperproperty" tied to TLC's single-worker BFS queue. A successful run supports the claim that at least one complete matching refinement exists. A reported CCFSpec counterexample can come from a different, failing branch even when another branch matches, so failure alone does not prove that no matching refinement exists. A Lean certificate directly checks one complete existential witness and avoids this ambiguity.

Do not put search in the trusted core

Keep Step relational and prove a small executable checker sound. An external tool may resolve nondeterminism and emit a certificate; Lean only verifies it. This mirrors proof-producing automation and avoids reimplementing TLC's state-space engine in Lean.

08 / Migration plan

How to start porting ccfraft.tla

Do not begin by transliterating all 1,779 lines. First establish the representation and proof pattern on a CCF-specific local slice, then add distributed mechanisms behind stable interfaces.

Recommended first slice: signed-commit core

Use a singleton configuration and model only logs, terms, roles, commit indices, ClientRequest, SignCommittableMessages, and a specialized AdvanceCommitIndex whose quorum guard is proved equivalent to the singleton case. Prove TypeInv, SignatureInv, and MonoLogInv, plus a concrete client-request/sign/commit path.

Why this slice: it exercises per-server functional updates, sequences, content variants, guarded actions, bundles, and a defining CCF deviation from Raft - without network messages or dynamic reconfiguration. Alternatively, a multi-server static slice must retain configurations, matchIndex, and quorum calculation; otherwise it silently weakens commit semantics.

Representation choices for that slice

Servers

Finite, inhabited key type

State fields use total functions Server -> .... Initialization needs a chosen start : Server or Nonempty Server; quorum operations need Fintype Server and decidable equality.

Entries

Typed sum, not record tags

EntryContent := transaction | signature | reconfiguration | retired, with payloads attached to the relevant constructor. This makes impossible record shapes unrepresentable, but narrows the raw TLA+ state space. Prove encode/decode correspondence or that all reachable TLA+ entries have this canonical shape.

Logs

List plus index API

Store Server -> List Entry. Isolate indexing, prefix, append, truncate, and last-committable operations behind lemmas so proofs do not unfold list arithmetic everywhere.

Roles

Inductive state

LeadershipState and MembershipState become inductive types. Exhaustive cases replace repeated membership tests over symbolic constants.

Indices

Choose one convention

Lean lists are zero-based; TLA+ sequences are one-based and use zero as "none". Keep an explicit Raft index wrapper or a carefully specified conversion boundary. Do not mix conventions in actions.

Updates

Pure old-state reads

Every action returns a new structure. Compute coupled values in a let from the old state, then update fields together. Add simplification lemmas for per-server updates immediately.

Freeze semantics and choose representations

Write a mapping table before proofs. Use an inductive EntryContent, an Entry structure, Server -> List Entry for logs, and explicit state fields. Decide whether indices are zero-based in Lean or preserve TLA+'s one-based view behind helper functions. Prefer one internal convention and prove boundary lemmas.

Build the local signed-log vertical slice

Implement initialState, pure next-state functions, Step constructors, three properties, their bundle, initializer proof, per-action preservation, Reachable, and one non-vacuity example. This gives an end-to-end template.

Add elections under one static configuration

Add votes, roles, timeouts, vote request/response, and BecomeLeader. Express quorum intersection as a reusable assumption or theorem over a configuration abstraction. Target one-leader-per-term and leader log prerequisites.

Add the network and log replication

Model messages as typed data rather than loose records. Add send, receive, update-term, append request/response, conflict truncation, and stale-message handling. Target log matching, monotonic terms, and leader completeness as a joint inductive bundle.

Add reconfiguration and retirement last

Configurations change the quorum theorem and couple logs, membership phases, and commitment. Add them only after static Raft safety is stable. Treat pre-vote, check-quorum, and retirement as separate extensions with regression examples.

Add transition properties before temporal liveness

Reachability induction handles state invariants, but ccfraft.tla also has safety formulas over current/next pairs: committed-log append-only, monotonic commit and term, permitted log changes, and never committing prior-term entries. Prove these for every real Step and separately prove the reflexive stutter case. Infinite traces or another temporal layer are still needed for exact temporal and fairness/liveness statements.

The current port's 17-clause CoreBundle is the fixed point ordinary Lean automation could preserve across all ten actions; the remaining properties need another mutually supporting layer.
09 / Reuse

A repeatable porting recipe

This applies beyond Raft: disaster recovery, governance, and smaller TLA+ protocols can use the same progression.

Specify

Make the relation exact

Translate state, derived operators, initialization, guards, and simultaneous updates. Keep a source-to-target mapping table.

Execute

Rule out vacuity early

Instantiate finite concrete types and prove representative action paths are reachable before investing in invariants.

Prove

Find the inductive bundle

Prove initialization, then preservation per action. Add supporting invariants when an action exposes a missing fact.

Audit

Expose the trust boundary

Print axioms, reject sorryAx, report open obligations, and distinguish proof gaps from translation gaps.

Validate

Separate search from checking

Let untrusted tooling find witnesses. Prove that a small Lean checker accepts only legal model executions.

Scale

Add one semantic dimension

Static before dynamic configuration; local before networked; state and transition safety before liveness; deterministic replay before partial traces.

Concrete next commit

Create CCFRaft/Model.lean with the signed-log state and three actions, then add one failing preservation test/theorem target for SignatureInv. Complete that vertical slice before introducing messages. It is small enough to review and rich enough to invalidate bad representation choices.
